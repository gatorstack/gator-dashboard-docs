# Gator Dashboard Docs: обязательный контекст

Отдельный Git-репозиторий `gator-dashboard-docs`.
Docusaurus, русский язык. Документирует Gator Dashboard и связанные Gator Dex,
Gator Cost/OpenMeter. Короткий запрос в этом каталоге относится к документации.

## Аудитория и формат сайта

Пользователь прямо уточнил: это документация **пользователя и администратора**,
образец — документация Argo CD. Основные разделы: обзор, понятия, начало работы,
руководство пользователя, руководство администратора, справочник сущностей, FAQ.
Пиши, как установить и настроить решение, что означают сущности и как решать
практические задачи. Давай полные YAML и последовательные команды с явным
целевым контекстом, ожидаемым результатом и нужными предварительными условиями.

В публикуемом `docs/` не должно быть git diff, исходников приложения, инструкций
разработки, ТЗ/шаблонов, отчётов тестирования, digest/revision учебных деплоев,
локальных путей автора, служебной синхронизации или архивов старой реализации.
Не отправляй читателя в соседний checkout за обязательными шагами инструкции.
Команды Helm с путями к chart полученного комплекта допустимы: публичный
Helm repository пока не опубликован. Не выдумывай адреса поставки.

Исходники и внутренние отчёты можно использовать как доказательство при написании,
но публикуй самостоятельное объяснение для оператора. `internal/source-snapshots/`
и `internal/previous-site/` находятся за пределами Docusaurus docs path и не
должны получать маршруты или ссылки из опубликованных страниц.

## Начало каждого нового чата

1. Прочитай этот файл, README и текущий git diff, включая staged.
2. Прочитай затронутые руководства в `docs/` и AGENTS.md исходного проекта.
3. Для Dashboard проверь `../gator-dashboard/docs/requirements/` и его diff;
   для Dex — `../gator-dex/docs/gator/requirements.md`; для Cost — его README,
   `docs/requirements.md`, `docs/decisions.md` и `docs/implementation.md`.
4. Сверяй документацию с текущими исходниками и требованиями. Прошлые результаты
   live-проверок не являются текущим состоянием кластера.

## Обновление обязательно

Каждый чат, меняющий поведение Gator Dashboard, аутентификацию, IAM/роли, CRD,
API, каталог, квоты, биллинг или эксплуатацию, обновляет соответствующие
руководства **в этом репозитории в той же задаче**. Это относится и к чатам,
работающим из родительского каталога или соседних репозиториев компонентов.
Нельзя завершать такую задачу с заведомо устаревшим описанием поведения.

- Сначала обнови требования/технический документ в исходном репозитории;
  существующие контракты и чужие изменения сохраняй.
- Обнови соответствующие страницы `docs/user-guide/`, `docs/operator-manual/`,
  `docs/reference/`, `docs/concepts.md` и `docs/getting-started.md` по смыслу.
  `docs/reference/` теперь содержит авторский справочник сущностей/параметров,
  а не копии файлов репозиториев.
- Выполни `npm run docs:sync`: внутренние снимки формируются из рабочих деревьев,
  включая незакоммиченные изменения. Генерируемые `internal/source-snapshots/`
  и `sources-manifest.json` вручную не редактируй. Синхронизация не обновляет
  руководства автоматически и не заменяет их ручное обновление.
- Выполни `npm run docs:check`, `npm run build`, `git diff --check`.
  При изменении навигации/оформления проверь сайт в desktop и mobile.
- Если исходный репозиторий недоступен, явно укажи ограничение; не заменяй
  подтверждённое описание предположениями и не объявляй синхронизацию успешной.

## Контракты и границы

- Dashboard — `../gator-dashboard`, Dex — `../gator-dex`, Cost — `../gator-cost`.
- Требования приложения остаются в исходных проектах; сайт содержит самостоятельные
  руководства пользователя/администратора и собирается без соседних checkout.
- Роли — native Kubernetes RBAC. User/Group не назначают роли автоматически.
  Сохраняй точные имена `authentificated`, `projectviewer` и аннотацию
  `iam.gatorstack.dev/display-name`.
- Предопределённые ClusterRole: auditor/viewer/editor/owner, группы через
  `iam.gatorstack.dev/role-group`. Продуктовые роли подключаются через
  `rbac.roleCatalog.products` при наличии реального API; общие роли собираются
  native aggregationRule. IAM подключён: iam.auditor/viewer читают проектные
  Role/RoleBinding, iam.editor меняет Role, iam.owner управляет назначениями.
  Из карточек создаётся только RoleBinding текущего проекта. Общие
  User/Group/ClusterRole читаются через authentificated всеми system:authenticated;
  глобальные изменения User/Group остаются у кластерного администратора.
  Role iam.passwords.editor отдельно в credentials namespace, без auto-binding.
- Актуальный Cost 0.2 использует OpenMeter и целые начатые минуты. История 0.1
  с OpenCost и секундным расчётом хранится отдельно и явно помечается архивом.
- Cost admin UI пока самостоятельный: Dashboard/Dex SSO и tenant RBAC в нём
  не реализованы. Не выдавай planned-интеграцию за готовую.
- Документационные правки не требуют деплоя Dashboard, Dex или Cost.
  Развёртывание сайта/публикацию выполняй по отдельному запросу пользователя.

## Секреты и диагностика

Никогда не добавляй реальные пароли, токены, DSN, kubeconfig, Secret data,
приватные конфиги или backup в документацию/manifest/Git. В примерах допустимы
ссылки на Secret и условные данные. Не импортируй `private/`.
Для диагностики study используй `oc` с явным kubeconfig
`../other/cozy-study-k8s/private/kubeconfig`, сначала проверь
целевой сервер; не переключай глобальный контекст. Данные Secret используй
только локально. Наличие записи о прошлом деплое не доказывает состояние сейчас.
