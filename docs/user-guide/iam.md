# Пользователи, группы и доступ

Откройте «Все сервисы → IAM». Доступные действия зависят от вашей роли.
Обычному пользователю права управления учётными записями не выдаются автоматически.

| Раздел | Для чего используется |
| --- | --- |
| Пользователи | Создание, просмотр, блокировка и смена локального пароля |
| Группы | Объединение пользователей для общих назначений доступа |
| Роли | Просмотр предопределённых и собственных наборов разрешений |
| Права доступа | Назначение и отзыв роли пользователя, группы или ServiceAccount |

## Пользователи

Пользователи общие для кластера: смена проекта не создаёт отдельную учётную
запись. Для локального пользователя нажмите «Добавить пользователя», укажите
техническое имя, полное имя и пароль с подтверждением. Для внешнего входа
выберите внешний тип и identities, согласованные с администратором провайдера.

Через карточку можно изменить полное имя, заблокировать пользователя или сменить
локальный пароль. Пароль и его хеш в карточке не показываются. Удаление требует
подтверждения имени. После удаления проверьте оставшиеся группы и назначения:
они не удаляются автоматически вместе с пользователем.

## Группы

Создайте группу и выберите участников. Изменение состава влияет на права,
которые уже назначены этой группе. Оно не создаёт новых назначений ролей.
Вложенные группы не поддерживаются.

## Выбрать роль

Раздел «Роли» по умолчанию показывает каталог с группами «Общие роли» и группами
подключённых продуктов. Поиск работает по названию, группе и техническому имени.
Предопределённые роли доступны для чтения; их меняет администратор установки.
Системные и собственные роли открываются в режиме «Все роли Kubernetes».

Общие уровни: **Аудитор**, **Наблюдатель**, **Редактор**, **Владелец**.
Фактический набор прав зависит от подключённых продуктов —
[сравнение ролей](../reference/roles.md).

## Назначить доступ

1. Выберите проект, затем IAM → Права доступа → «Назначить роль».
2. Выберите область «Проект» и нужную ClusterRole, например «Аудитор».
3. Выберите пользователя, группу или ServiceAccount и сохраните назначение.
4. Проверьте результат под учётной записью получателя.

Область «Кластер» выдаёт доступ через ClusterRoleBinding и предназначена для
администраторов кластера. Для доступа к одному проекту используется область проекта.

Если список ролей недоступен, можно указать известное техническое имя вручную.
Это не отменяет проверку права на назначение. Для смены роли создайте новое
назначение: у существующего binding поле роли неизменяемо.

## Назначить из карточки

В карточке пользователя или группы нажмите «Назначить роль» в блоке
«Назначенные роли». Получатель уже выбран; выберите роль и сохраните.
В карточке роли эта кнопка фиксирует роль: остаётся выбрать пользователя,
группу или ServiceAccount. Имя назначения заполняется автоматически,
при необходимости его можно изменить.

Во всех трёх случаях назначение действует только в текущем проекте из
верхнего переключателя. Общая ClusterRole не означает выдачу прав всему
кластеру: создаётся RoleBinding проекта. Для другого проекта сначала
переключите проект. После сохранения карточка остаётся открытой, назначения
обновляются автоматически, сообщение содержит ссылку на результат.

Для назначения роли не требуется право менять пользователя, группу или
саму роль. Нужны права создания RoleBinding проекта и назначения выбранной
роли. Если Kubernetes отказал, сообщение остаётся в форме, введённые данные
сохраняются.

## Роли IAM

| Роль | Что позволяет в проекте |
| --- | --- |
| iam.auditor | Смотреть Role и назначения RoleBinding |
| iam.viewer | Те же права: отдельного слоя данных у IAM пока нет |
| iam.editor | Дополнительно создавать, менять и удалять местные Role |
| iam.owner | Дополнительно управлять RoleBinding и назначать роли каталога |

Все эти роли открывают соответствующий проект. Общий список пользователей,
групп и ClusterRole читают все вошедшие пользователи под собственным токеном.
Изменять общие учётные записи по проектной роли нельзя: это полномочия
кластерного администратора. Управление локальными паролями делегируется
отдельной служебной ролью только в namespace credentials.

## Отозвать доступ

Удалите назначение. Если доступ сохраняется, проверьте другие прямые назначения
и роли групп. Удаление одного binding не отменяет остальные. Карточки показывают
доступные назначения, а не гарантированный полный расчёт всех прав пользователя.

Настройка прав для администраторов IAM описана в
[руководстве администратора](../operator-manual/rbac.md).
