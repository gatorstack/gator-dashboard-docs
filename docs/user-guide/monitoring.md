Откройте **Мониторинг → Дашборды** в выбранном проекте. Сервисные дашборды
устанавливаются вместе с продуктами: Compute показывает CPU, память, диски и сеть
ВМ; Object Storage — трафик, занятое место, объекты и квоты бакетов.

В карточке дашборда выберите период, интервал обновления и ресурс. «Все» показывает
ресурсы текущего проекта. Пустая панель означает отсутствие подходящих рядов за
период; она не подставляет ноль вместо недоступных данных. Bucket stats обновляются
асинхронно, поэтому изменения объектов появляются с задержкой. Физический размер
RGW не включает полную стоимость репликации Ceph. Отрицательный лимит bucket quota
означает отсутствие индивидуального ограничения.

Дашборды создаются и изменяются только через ресурс Kubernetes
`MonitoringDashboard`: с помощью Helm, GitOps или Kubernetes API. В консоли
доступен просмотр сервисных и проектных дашбордов, без создания, копирования и
редактора. На вкладке **Дашборды проекта** отображаются определения из namespace
проекта. Уже существующие определения сохраняются. Формат ресурса и пример YAML
описаны в [справочнике Monitoring API](../reference/monitoring.md#дашборд-из-чарта-продукта).

## Экспорт метрик

Во вкладке **Экспорт метрик** нажмите **Добавить экспорт** и укажите:

1. Имя подключения и remote_write URL Prometheus-совместимого получателя.
2. Интервал от `10s` до `1h`, по умолчанию `30s`.
3. Авторизацию: без авторизации, Basic Auth, Bearer Token или расширенную
   конфигурацию для OAuth2, TLS/mTLS и других параметров VictoriaMetrics.
4. Состояние «Экспорт включён».

Отправка начинается после создания native VMAgent. Передаются текущие ряды только
этого проекта; накопленная история не выгружается. Потеря связи с получателем
использует ограниченную дисковую очередь. Длительный отказ может привести к потере
старейших непереданных данных. `Running` означает готовность агента, а не
подтверждение доступности внешнего получателя.

Пароли, токены и сертификаты сохраняются в отдельном Kubernetes Secret. Они не
возвращаются при открытии формы. При редактировании пустой JSON учётных данных
сохраняет их при прежней конфигурации подключения. Для смены подключения или
credentials укажите полный набор используемых ключей заново. Выключение останавливает агент; удаление также
удаляет его очередь и управляемые учётные данные. Метрики в основном хранилище
проекта сохраняются.

По умолчанию частные адреса получателей запрещены. Для собственного хранилища
во внутренней сети попросите администратора разрешить его hostname в политике
MonitoringBackend. Локальные и link-local адреса недопустимы.

### Расширенная авторизация

Поле конфигурации соответствует native `VMAgentRemoteWriteSpec`. Пример OAuth2:

```json
{
  "url": "https://metrics.example.com/api/v1/write",
  "sendTimeout": "30s",
  "oauth2": {
    "client_id": {"secret": {"name": "credentials", "key": "client-id"}},
    "client_secret": {"name": "credentials", "key": "client-secret"},
    "token_url": "https://identity.example.com/oauth/token",
    "scopes": ["metrics.write"]
  }
}
```

В отдельное поле новых учётных данных передайте JSON со строковыми ключами
`client-id` и `client-secret`. Имя `credentials` в форме заменяется ссылкой на
Secret этого экспорта. Для mTLS используются `tlsConfig.ca.secret`,
`tlsConfig.cert.secret` и `tlsConfig.keySecret` с такими же ссылками.
Произвольные Secret, пути к файлам, замена источника и фильтров проекта запрещены.

Во вкладке **Метрики** доступен диагностический список до 1000 рядов за последние
5 минут: имя, все labels и последнее значение. Поиск работает по имени и labels.
Для полноценного просмотра используйте дашборды с более узкими запросами.

## Почему проект видит только свои данные

Gator проверяет права текущего пользователя в Kubernetes и UID выбранного проекта.
Затем закрытый прокси использует отдельную учётную запись VMAuth с фиксированным
маршрутом в tenant этого проекта. Браузер не получает пароли VictoriaMetrics и не
выбирает tenant ID. Настройки PromQL или экспортного получателя не расширяют
область доступа. Общая Grafana платформы предназначена администраторам.

## Логи

«Мониторинг → Логи» открывает общий редактор LogsQL с выбором источника и
источника, гистограммой, таблицей и JSON. Роль logging.viewer открывает все
клиентские логи проекта, независимо от доступа к заказам. [Работа с запросами](logging.md).
