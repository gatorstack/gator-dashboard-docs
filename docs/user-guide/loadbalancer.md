# Балансировщик L4

Откройте **Все сервисы → Infrastructure → Балансировщик L4**.

Сначала создайте целевую группу: выберите регион, добавьте внутренние
IPv4-адреса приложений и их подсети. Подготовьте маршруты и разрешите в группах
безопасности трафик от балансировщика, включая health checks.

Создайте балансировщик, выбрав регион, VIP-подсеть и внешний либо внутренний
тип. Внешний адрес можно выделить автоматически или выбрать из предварительно
свободных адресов из общего списка **Compute**. Отдельного списка адресов
у L4 нет. Автоматически выделенный адрес также виден в общем списке Compute.

Добавьте обработчик: имя, TCP/UDP, входной порт, порт приложения и целевую
группу. Настройте HTTP/TCP-проверку, её порт, HTTP-путь, время ожидания, интервал
и пороги успешных/неуспешных попыток. Для HTTP приложение должно возвращать 200.
Время ожидания должно быть меньше интервала. Можно добавить несколько обработчиков.

После создания дождитесь **Активен**: конфигурация заказа применена.
Недоступность приложения не делает заказ ошибочным. Во вкладке **Целевые
ресурсы** состояние каждой TCP-цели поступает из мониторинга Octavia:
**Да** — цель доступна, **Нет** — недоступна. Для UDP, потери мониторинга и
отсутствующих свежих метрик показывается **Нет данных**. Проверьте приложение,
health endpoint, маршруты и правила безопасности при недоступных целях.

Если сохранена вкладка **Логи**, она содержит архив прежних событий состояния
за последние 30 дней; нужен `logging.viewer`. Новые состояния берутся из
мониторинга. Общие журналы доступны в **Мониторинг → Логи**.

Регион, тип, VIP-подсеть и режим выделения адреса выберите при создании.
Обработчики, состав групп, описание, метки и защита редактируются. Изменение
портов или удаление обработчика может прервать соединения.

При открытии редактирования каждый обработчик показывает уже выбранную
целевую группу. Повторно выбирать её для изменения описания или других
настроек не требуется.

Перед удалением отключите защиту. Используемые группы, подсети и резервный
адрес защищены от удаления. Автоматический адрес удаляется с балансировщиком;
предварительно зарезервированный адрес сохраняется для следующего заказа.

Подробности установки, прав, сети и API — в
[руководстве администратора](../operator-manual/loadbalancer.md).

Для чтения таблицы метрик нужны права на ProjectMonitoring/project: назначьте
monitoring.auditor либо monitoring.viewer в проекте. Продуктовая роль L4 сама
по себе не открывает все метрики проекта.


При создании и редактировании можно выбрать **Группы безопасности** из VPC
того же проекта и региона. Пустой список включает автоматические правила
Octavia. При выборе своих SG разрешите в них входные порты обработчиков.
Для доступа к backend через правило «из той же SG» назначьте одну SG интерфейсу
балансировщика и backend-ВМ и разрешите в ней целевой порт. SG самих backend-ВМ
балансировщик не изменяет.

Выбор SG применяется без пересоздания VIP и внешнего адреса. Во время
изменения кратковременно приостанавливается сбор метрик; доступность backend
после применения правил по-прежнему не влияет на успешность заказа.
Служебная группа сохраняет доступ scraper к порту метрик. Правила SG
складываются: не открывайте этот служебный порт (по умолчанию TCP 8088) общим
сетям в пользовательских SG.
