---
title: "S3: бакеты, учётки и ключи"
---

S3 хранит объекты в бакетах. В проекте доступны бакеты, служебные S3-учётки,
их ключи доступа и назначения прав. Это отдельные учётные записи S3 API;
они не заменяют пользователей входа в Gator.

## Создание бакета

Откройте **S3 → Бакеты → Создать**. В форме **Создать бакет** сначала укажите имя,
затем заполните секции в следующем порядке:

1. **Основные настройки** — максимальный размер, HOT или COLD и метки.
   По умолчанию установлен лимит 50 ГБ (50 × 1024³ байт). Можно изменить число
   и единицу или отключить ограничение переключателем.
2. **Доступ** — отдельно выберите **С авторизацией** или **Для всех** для
   чтения объектов, чтения списка объектов и чтения настроек. По умолчанию все
   три режима требуют авторизации. Публичное чтение объектов само по себе
   не открывает список или настройки, а чтение списка не открывает содержимое.
3. **Версионирование** — переключатель **Хранить историю изменений объектов**.

После принятия заказа дождитесь готовности в карточке. Скопируйте техническое
S3-имя бакета, endpoint и регион.
Метки редактируются так же, как при заказе ВМ: нажмите **Добавить метку**,
укажите ключ и значение. Метка появится плашкой; нажмите её для изменения
или крестик для удаления. Повторяющиеся ключи не принимаются.

Короткое имя в консоли и техническое имя S3 различаются: префикс технического
имени обеспечивает изоляцию проектов.

HOT/COLD — классы размещения. Внешний Ceph определяет их физические свойства.
На установке с логическими классами это разные пулы общих дисков, без гарантии
разной производительности. Класс бакета выбирается при создании; перенос старых
данных в другой класс этим действием не выполняется.

Бакет закрыт по умолчанию. Включённое версионирование можно приостановить,
но вернуть в исходное состояние off нельзя. Лимит размера применяется к отдельному
бакету в Ceph и не меняет квоты других бакетов проекта. Свойства Ceph и учёт
версий влияют на фактическое использование места.

Заказ создаёт один `S3Bucket` в namespace проекта. Crossplane Composition
создаёт и согласовывает дочерние Bucket и BucketPolicy. До их готовности заказ
остаётся в подготовке. Ошибки провайдера видны в карточке, на вкладке
**Диагностика**; закрытие формы их не удаляет. Повторять заказ того же имени
не нужно: исправьте параметры существующего ресурса.

## Изменение размера и публичного доступа

Откройте бакет и нажмите **Изменить**. В блоке **Основные настройки** можно
включить или отключить лимит, изменить максимальный размер и метки. Нажмите
**Сохранить параметры**; страница останется открытой для дальнейшей настройки.
Версионирование сохраняется той же кнопкой.

В блоке **Доступ** задаются три независимых режима чтения. Квота, версии,
метки и доступ сохраняются одной кнопкой **Сохранить параметры** в одном CR.
Если все режимы требуют авторизации, публичных разрешений в политике не останется.
Права служебных учёток и их ключи это действие не меняет.

Произвольная JSON policy находится в расширенных настройках и на вкладке
**Bucket policy → Изменить JSON policy**. Непустой документ имеет приоритет
над тремя переключателями. Он сохраняется при изменении размера или меток;
чтобы снова использовать переключатели, явно очистите документ до `{}`.

В **Обзоре** отображаются максимальный размер (или **Без ограничения**) и
каждый режим публичного чтения. Значения политики читаются из наблюдаемого
состояния CR. После сохранения дождитесь синхронизации контроллера. Для
произвольной политики обзор указывает, что доступ задаётся ею: учитывайте
условия этой политики при проверке реального запроса S3.

## Учётка и доступ к бакету

В **Учётки** создайте учётку в доступном S3-подключении. Новая учётка не имеет
доступа к объектам. В карточке бакета выберите **Выдать доступ**, затем учётку
и один из режимов:

- **Чтение** — список и чтение объектов выбранного бакета.
- **Чтение и запись** — чтение, загрузка и удаление объектов выбранного бакета.

Вкладка **Доступ** показывает назначения. Изменение назначения меняет режим;
удаление отзывает его, сохраняя бакет, данные, учётку и ключи. Разрешение одного
бакета не открывает другой бакет. Выдавайте права отдельно для каждого.
Оба режима также разрешают получать список названий **всех бакетов текущего
проекта**. Список не фильтруется по персональным назначениям; права на содержимое
остальных бакетов не выдаются. После отзыва последнего назначения исчезает
и право на список. Бакеты других проектов в него не входят.
Права управления ресурсами в Gator и права S3 API — разные настройки.

Учётка, ключ и назначение доступа также создаются как отдельные S3User,
S3AccessKey и S3BucketAccess в namespace проекта. Их дочерними ресурсами
управляет Crossplane. При обновлении существующие учётки и ключи сохраняются;
повторно выпускать ключи или перенастраивать приложения не нужно.

## Получение ключей

Откройте **Учётки**, выберите нужную учётку и перейдите на вкладку
**Ключи доступа**. Здесь сразу видны её ключи: Access key ID отображается
открыто, Secret access key можно показать или скопировать кнопкой рядом.
Переходить в карточку ключа и открывать отдельное окно получения не требуется.

Кнопка **Создать ключ** находится на этой же вкладке. Задайте имя: после
отправки вы вернётесь к ключам учётки. Если Secret ещё создаётся, интерфейс
подождёт и повторит чтение. При длительной подготовке доступна кнопка повтора.
В каждой карточке также есть скачивание JSON и переход к управлению ключом.

При уходе со вкладки значения очищаются. Повторное открытие читает существующие
ключи из Secret и не выпускает новые.

Для просмотра нужны отдельные права чтения connection Secret. Сейчас они
включены в проектные роли S3 редактора и владельца. Наблюдение за ресурсом
само по себе не выдаёт секретный ключ. Администратор может уточнить эти права
обычными средствами Kubernetes RBAC.

Используйте endpoint и регион из карточки вместе с ключами в S3-клиенте.
Например, настройте защищённый AWS profile вне Git, затем обращайтесь к известному
техническому имени бакета. Новые назначения доступа разрешают список бакетов
проекта; для назначений, созданных до обновления, оператор должен выполнить миграцию.

В Database Client для VS Code выберите S3 / Common / Minio, укажите host S3
endpoint без `https://`, порт 443, включите HTTPS и Path Style. Регион возьмите
из карточки бакета, Access Key и Secret Key — со вкладки учётки. Общий список
отобразит бакеты проекта, а чтение содержимого будет разрешено только там,
где учётке выдан доступ.

Для ротации создайте второй ключ, переключите приложение, затем отключите или
удалите прежний. Отключённый ключ можно включить снова; удалённый ключ отозван.
Secret access key не хранится в истории действий. Access key ID может присутствовать
в нативном CR как публичный идентификатор ключа.

## Удаление

Сначала отзовите назначения доступа и удалите независимые настройки CORS,
lifecycle и website. Непустой бакет не удаляется автоматически:
очистите объекты и, при наличии версионирования, версии и delete markers.
Принятие удаления в Gator отделено от завершения операции во внешнем Ceph;
XR остаётся видимым до удаления дочерних CR. Ошибку native Bucket можно
прочитать в **Диагностике**. После очистки данных удаление продолжится.
Автоматический purge не включён.

Перед удалением учётки удалите её ключи и назначения. Бакеты принадлежат аккаунту
проекта и не исчезают при удалении прикладной учётки.

## Содержимое бакета

Карточка открывается на вкладке **Обзор**. Поле **S3 бакет** содержит имя для
S3-клиента, **Регион** — его настройку региона. Над заголовком небольшим серым
текстом показано техническое имя Kubernetes-ресурса; оно используется в его URL
и отличается от имени бакета в S3. Условия и ошибки контроллера находятся на
вкладке **Диагностика**. Вернуться к списку можно через крошки или меню S3.
Для загрузки, скачивания, папок, копирования и работы с версиями используйте
внешний S3-клиент или SDK с endpoint, регионом и ключами из карточки ключа.
Dashboard управляет бакетами и их настройками через Kubernetes GVK.

## CORS, lifecycle и сайт

Действия **Настроить CORS**, **Настроить Lifecycle**, **Настроить Website** создают
по одной конфигурации бакета. После создания открывайте её из соответствующей
вкладки для изменения или удаления. CORS задаёт origins, методы, заголовки и
время кеша preflight; он не выдаёт S3 permissions. Lifecycle управляет переходом
HOT/COLD, сроком хранения текущих и старых версий, незавершёнными multipart.
Правила исполняет RGW асинхронно; сохранение формы не означает немедленного удаления.

Website задаёт индексный документ и, при необходимости, документ ошибки.
Другой режим перенаправляет все запросы на заданный host/protocol; он исключает
индекс, документ ошибки и правила маршрутизации. Для обычного сайта доступны
условные redirects по префиксу или коду ошибки.
Загрузите эти файлы и явно откройте публичное чтение, если сайт предназначен
для анонимных посетителей. Адрес отдельного website endpoint предоставляет
администратор; S3 API endpoint не заменяет website endpoint.

Для публичного сайта откройте **Изменить → Доступ → Чтение объектов → Для всех**.
Листинг и запись этим выбором не открываются. На вкладке **Bucket policy** можно
изменить произвольный JSON через основной S3Bucket. Для закрытия доступа очистите
произвольный документ до `{}` и установите три режима **С авторизацией**.
Дочерняя policy согласовывается автоматически; отдельно удалять её не требуется.
Проверяйте Principal, Action и Resource перед сохранением. Не помещайте
credentials в policy. Назначения учёткам на вкладке **Доступ** сохраняются отдельно.

KMS, собственные домены HTTPS и облачный аудит будут отдельными этапами.

## Имя уже занято

При повторном имени в одном проекте форма показывает «Ресурс с таким именем уже
существует в этом проекте. Укажите другое имя». Введённые значения сохраняются,
сообщение остаётся до повторной отправки или сброса. Исправьте имя и отправьте
форму снова. Один и тот же короткий заголовок допустим в разных проектах:
фактические S3-имена содержат разные префиксы.

Если полное S3-имя заранее занято другим аккаунтом Ceph, запрос на CR может быть
принят, но бакет не станет готовым. Откройте **Диагностика**: состояние провайдера
содержит BucketAlreadyExists. Чужой бакет автоматически не принимается под
управление. Выберите свободное имя; существующий бакет и его данные сохраняются.

Для перенесённого бакета повторный заказ также может быть принят как отдельный
запрос, но Composition отклонит его до создания второго native CR.

Если полный идентификатор S3 уже занят другим аккаунтом, список и карточка
показывают «Конфликт имени». В «Диагностике» доступен ответ провайдера.
Такой запрос не получает доступ к существующему бакету.
