---
title: Аудит действий
---

В проекте откройте **Мониторинг → Аудит → Трейлы**. Трейл выбирает события
проекта и доставляет их в одно назначение. Для нескольких назначений создайте
несколько трейлов: например, в логирование для расследований и в S3 для архива.

## Создать трейл

1. Нажмите **Создать** и задайте имя.
2. Выберите источники: действия в консоли, Kubernetes API, S3 API.
3. Выберите категории и чтение/запись. Управление ресурсами относится к management;
   операции S3 с данными — к data.
4. При необходимости задайте включаемые и исключаемые типы событий.
   Поддерживается точное имя или `*` в конце: `kubernetes.core.configmaps.*`,
   `console.s3.*`, `s3.put_*`. Исключение имеет приоритет над включением.
5. Выберите назначение и сохраните трейл.

Сбор начинается с момента создания. Отключённый трейл можно включить снова;
при этом начинается новое окно сбора. Пропущенный период автоматически не
восстанавливается. Изменения применяются асинхронно.

## Назначения

**Логирование проекта.** События доступны в **Мониторинг → Аудит → События аудита**
и во вкладке событий трейла. Используйте период, LogsQL и фильтры `actor`,
`event_type`, `resource`, `outcome`. Поле `event_id` помогает найти ту же операцию
в других назначениях. Проектное логирование хранит данные 30 дней.

**S3.** Выберите существующий бакет и пользователя S3 текущего проекта. Пользователь
должен иметь право `s3:PutObject` на выбранный префикс. Сам выбор пользователя
прав не добавляет. Создателю трейла нужны права просмотра бакета/пользователя и
создания S3-ключей. Для каждого трейла создаётся отдельный ключ выбранного
пользователя; вводить access key и secret key в форме не требуется.

Архив содержит gzip JSON: `<префикс>/<UID трейла>/YYYY/MM/DD/<event_id>.json.gz`.
Срок хранения задайте средствами бакета. Используйте отдельного пользователя
архива и отдельный префикс: служебные PutObject выбранного writer в архивные префиксы
исключаются из аудита, чтобы избежать рекурсивной записи. Чтение архива и действия
других пользователей сохраняются в аудите. Не храните в этих префиксах прикладные
данные выбранного writer, аудит записи которых необходимо сохранить. После удаления трейла
созданный им ключ отзывается, записанный архив остаётся.

**SIEM.** Укажите хост, порт, TCP/UDP/TLS и формат syslog RFC3164 либо RFC5424.
Событие передаётся в CEF. TCP/TLS используют завершение строки, UDP — одну
датаграмму на событие. Для TLS проверяются цепочка доверия и имя сервера;
при необходимости укажите Secret с `ca.crt` и отдельный Secret с `tls.crt`/`tls.key`
для клиентского сертификата. Secret должен находиться в проекте, а создателю
трейла требуется право его чтения. Значения сертификатов и ключей в форме не вводятся.

TCP/TLS подтверждают запись в соединение, UDP — отправку датаграммы. Это не
подтверждение индексации SIEM. После настройки проверьте контрольное действие
в поиске принимающей системы. Для внутреннего Wazuh администратор может
подготовить TCP-приёмник; обычный HTTPS-адрес Wazuh Dashboard для syslog не подходит.

## Покрытие и смысл событий

Консоль публикует безопасную историю действий, Kubernetes — нативный Metadata
аудит API, S3 — нативные события RGW. Действия над ресурсами продуктов через
консоль и Kubernetes входят в эти источники, включая прямые `oc`/API обращения.
Служебный субъект указывается как service account, без подмены человеком.

`Accepted` означает принятие API-запроса, а не завершение создания ВМ или БД.
`Rejected` означает отказ API. Прямые вызовы внешних OpenStack API, SQL-запросы
и действия внутри гостевой ОС требуют собственных источников и не входят в это
покрытие. События без подтверждённого проекта не выдаются клиентам.

Тела API-запросов/ответов, содержимое Secret и объектов S3, пароли и cloud-init
не экспортируются. Системные события самого доставщика и технические обновления
его состояния исключаются, чтобы избежать обратной связи.

## Доступ и состояние

`audit.auditor` читает конфигурацию трейлов, `audit.viewer` дополнительно открывает
проектное логирование, `audit.editor` управляет трейлами. Доступ к логам — общий
для проекта: `audit.viewer`, как и `logging.viewer`, открывает все клиентские
источники этого проекта. Фильтр страницы аудита не является отдельной границей RBAC.

В карточке видны состояние, счётчик подтверждённых доставок, последняя доставка
и диагностика Crossplane. `Listening` означает ожидание событий, `Active` —
работающую доставку, `Disabled` — отключение. Ошибка подключения, отказ S3 или
замена закреплённого ресурса отображаются как неготовность.

При временной ошибке назначение повторяется из очереди. Возможны дубликаты;
для устранения повторов используйте `event_id`. Долгая недоступность может
превысить хранение очереди. Удаление трейла прекращает дальнейшую доставку и
удаляет его служебные зависимости, но не доставленные записи.
