# Настройки профиля

Нажмите на пользователя внизу левого меню и выберите **Настройки профиля**.
В нижнем меню показаны ваше полное имя и технический логин. После изменения
имени или фамилии полное имя обновляется сразу. На телефоне сначала откройте меню. Настройки доступны также со страницы
«Нет доступных проектов»: назначение роли в проекте для них не требуется.

## Профиль

Страница показывает данные вашей учётной записи User:

- Полное имя складывается из имени и фамилии.
- Имя и фамилия изменяются отдельно: нажмите карандаш, введите значение и сохраните.
- В разделе «Контакты» так же меняются электронная почта и номер телефона.
- В разделе «Аккаунт» показаны постоянный идентификатор User и дата его создания.

Изменение контактов не меняет логин, пароль, привязку внешнего провайдера или
подтверждённую почту у него. Для изменения этих параметров обратитесь к
администратору или в настройки соответствующего провайдера.
Если профиль одновременно изменился в другой вкладке, обновите страницу и
повторите изменение. При ошибке сохранения введённое значение остаётся в форме.

У старых учётных записей без отдельных имени и фамилии прежнее полное имя
показывается в поле имени. Его можно разделить вручную.

## Активные сессии

Раздел «Контроль входа в аккаунт» показывает каждую сессию отдельной строкой.
В заголовке виден исходный User-Agent: сведения о клиенте, например браузер и
операционная система. Ниже указаны приложение и время входа. Текущая сессия стоит
первой и отмечена словами «Вошли на этом устройстве». Для остальных показано
относительное время; точные даты входа и последней активности доступны через
**Подробнее**.

User-Agent сообщает клиент; это не подтверждённый идентификатор устройства.
Старые входы без сохранённого заголовка обозначаются «Неизвестное устройство».
Два входа в консоль с разных браузеров являются отдельными сессиями.
Список обновляется автоматически каждые 15 секунд и по кнопке «Обновить».

**Выйти** в строке завершает выбранную сессию. **Выйти везде** завершает все
такие сессии вашей учётной записи, включая текущую, во всех приложениях Dex и
привязанных провайдерах. Оба действия требуют подтверждения.
После выхода для продолжения работы понадобится аутентифицироваться повторно.
Это не завершает собственный сеанс у внешнего провайдера: он может предложить
повторный вход без пароля по своим правилам.

Консоль отклоняет следующий запрос завершённой сессии. Уже открытый поток
обновлений завершится по своему таймауту. Другие потребители выданного JWT,
например Kubernetes CLI, могут принимать его до окончания срока токена;
получить новый токен по отозванной сессии нельзя.

## Группы

Страница показывает все группы, в которые администратор добавил ваш User.
Самостоятельного изменения членства здесь нет. Отсутствие групп не означает
отсутствие доступа: роли могут быть назначены непосредственно пользователю.
Членство и права обновлённого JWT — разные сведения: изменение групп попадает
в токен при следующем обновлении.

## Вход с ServiceAccount

ServiceAccount — служебная Kubernetes-идентичность без личного User и сессий Dex.
Для неё настройки показывают пояснение. Чтобы редактировать личный профиль,
войдите через локальную учётную запись или провайдера Dex.
