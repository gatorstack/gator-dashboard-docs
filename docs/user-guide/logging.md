---
title: Логи заказанного ресурса
---

В карточке S3-бакета доступны вкладки **Access logs** и **Error logs**.
Access показывает запросы к этому бакету, Error — запросы с HTTP 4xx/5xx.
Логи хранятся 30 дней; доступны только записи, сделанные после создания текущего
заказа. Удаление заказа закрывает доступ к его логам. Новый бакет с тем же именем
не получает историю прежнего экземпляра.

Выберите сутки, 7 или 30 дней и нажмите **Обновить**. Поле поиска принимает слово,
request ID либо выражение LogsQL, например `http_status:=404`. Фильтр бакета
проверяется сервером и сохраняется при любом поиске. Для автоматического обновления
включите переключатель: каждые 5 секунд выполняется новый авторизованный запрос.
Отображаются до 200 записей; скачивание сохраняет именно текущий результат в NDJSON.
Уточните период и поиск, если записей больше.

Таблица содержит время, операцию, объект, HTTP-статус, S3 error code, request ID,
длительность и объём переданных данных. Общие daemon/debug ошибки RGW/Ceph,
учётные данные и внутренние адреса в этот источник не входят. 403 отражает
отказ в S3-запросе, а не право пользователя Dashboard читать чужой бакет.

Нужны доступ к проекту, чтение самого Bucket CR и отдельное разрешение чтения
проектного LogAccess. Штатные S3-роли включают его. Доступ к S3 по ключу приложения
сам по себе не открывает Dashboard и его логи. Запрос к чужому проекту/бакету,
устаревший UID или отозванные права не возвращают записи.

Если записей нет, проверьте выбранный период и выполните запрос к бакету внешним
S3-клиентом. Записи поступают асинхронно. При сообщении о неготовой identity
дождитесь готовности Bucket. При отказе в доступе обратитесь к администратору проекта.
