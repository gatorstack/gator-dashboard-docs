## Доступ через IAM

Роль **Просмотр логов** (`logging.viewer`) открывает все клиентские логи выбранного
проекта. Разделения по своим заказам нет; права на S3-бакеты или другие продуктовые
CR не требуются. Сами S3-роли доступа к логам не дают. Общие viewer/editor/owner
включают просмотр логов, auditor — нет. Между проектами доступ изолирован.

Для назначения выберите проект, IAM → Права доступа → «Назначить роль», группу
«Логирование» и «Просмотр логов». Роль **Управление доступом к логам**
(`logging.owner`) дополнительно управляет назначениями logging-ролей.
Отзыв всех предоставляющих просмотр назначений закрывает последующие запросы.

## Мониторинг → Логи

Выберите источник (например S3 Access logs или Error logs) и период: 5/30 минут,
час, 6 часов, сутки, 7/30 дней или собственные даты. Источник виден даже без
текущих заказов, если продукт подключён к платформенному логированию. Запрос включает все
сохранённые записи источника в проекте: в том числе удалённые заказы и бакеты
того же проекта вне каталога. Он не открывает служебные логи платформы.

Введите LogsQL и нажмите **Выполнить запрос** либо Ctrl/⌘+Enter. Можно добавить до
четырёх независимых запросов A–D. Каждый выполняется в одной и той же выбранной
области доступа. Например:

```text
*
http_status:=404
* | stats count() as count
* | stats count() as count by (operation)
```

Последние два примера используют разрешённую вычисляемую колонку `count` S3
источника. Для других продуктов разрешённые поля результата задаёт их чарт.
Синтаксис и имена полей — VictoriaLogs LogsQL; редактор не переводит язык Яндекса.

Гистограмма показывает количество **всех подходящих исходных записей** в периоде,
независимо от лимита строк таблицы. Агрегирующие pipes не меняют смысл этой
гистограммы. A–D отмечаются отдельными цветами. Таблица показывает до выбранного
лимита 100/200/500/1000 строк на запрос, включая разрешённые вычисляемые колонки.
Вкладка JSON, раскрытие записи, выбор колонок и NDJSON работают с этим же
результатом. В раскрытой записи поле можно добавить в первый запрос.

Автообновление повторяет последний выполненный запрос. Черновик редактора не
отправляется автоматически. Смена проекта/источника отменяет запросы и
очищает результаты. Кнопка «Источники» обновляет каталог источников. Удаление
заказа не закрывает доступ к его истории в проектном экране: она доступна в пределах
30 дней. При некорректном LogsQL исправьте синтаксис и повторите запуск.

## Карточка ресурса

Access/Error в карточке бакета — удобный фильтр на конкретный ресурс. Для открытия
самой карточки нужны обычные продуктовые права; для логов также нужна роль
логирования. Фильтр текущего UID/identity и времени создания ограничивает этот вид.
Полную проектную историю смотрите через «Мониторинг → Логи» без product CRUD.

Записи поступают асинхронно. Если выдача пуста, проверьте источник/период и
наличие запросов к S3. Error содержит только HTTP 4xx/5xx. URI, credentials,
общие daemon/debug сообщения и внутренние адреса в клиентский источник не входят.
